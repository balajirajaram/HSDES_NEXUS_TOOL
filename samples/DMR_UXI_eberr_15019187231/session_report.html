Final Analysis

The LTSSM trace confirms the root cause sequence precisely. During WR, the UXI link on S1 drops from 56G (entry 54: REC_RCVRLOCK@56G) to Gen1 base rate (entry 53: Gen1, x2 width) — this is an abrupt speed drop rather than a clean speed-change sequence. The LTSSM then enters 2.5G detection mode and attempts to detect the link partner three times:

NODET attempt 1 (entry 48, 457ns): S1 receiver squelch expired but no far-end signal detected → NODET arc.
NODET attempt 2 (entry 44, 449ns): Second detection window also fails → NODET arc.
DETALL (entry 40, 451ns): Third attempt finally detects the link partner → link trains successfully at 2.5G.

The two NODET cycles (~12ms each for DET_QUIET) mean the S1 deskew buffer is attempting lane alignment during a period where the link partner's signal was not yet reliably present. This causes deskewsts.dberr=0x1 to be latched. Notably, nodbmarkset=0x0 — the lane bitmap field is not populated — consistent with the error being logged before lane identity was established during early detection. The wide eberr bitmaps (0x8bff0000 / 0xefef0000, many lanes) confirm a bus-level alignment failure, not lane-specific SI.

S0's LTSSM (Passing_Loggers.log) goes through a clean REC_RCVRCFG_SPEED → ALLEQTS path with no NODET retries — demonstrating that S0's receiver successfully detects the partner on the first attempt. This S0/S1 asymmetry in detection is the root cause of the symptom being socket-specific.

All error registers (deskewsts.dberr, eberr, rxerrcnt, laneerrsts) are PF-type (sticky, cleared only by explicit reconfig or full power cycle). They accumulate across WR cycles, giving the appearance of growing BER when in fact each WR simply adds another sticky event. The link always trains successfully to 56G PAM4 — no functional impact to system operation.

Root Cause / Final Hypothesis

During warm reset, the S1 UXI link drops from 56G operational speed to Gen1 base rate (abrupt speed drop: REC_RCVRLOCK@56G → Gen1). When re-entering 2.5G NRZ detection mode, S1's receiver fails to detect the link partner in the first two 128µs detection windows (2× NODET arcs in the LTSSM). This delayed detection causes the UXI Deskew Buffer on S1 to log deskewsts.dberr=0x1 (lane deskew timeout, nodbmarkset=0x0 — error before lane identity established). Because deskewsts.dberr, eberr, rxerrcnt, and laneerrsts are all PF-type sticky registers, they accumulate across WR cycles without self-clearing. S0 is unaffected because its LTSSM recovers via the clean REC_RCVRCFG_SPEED→ALLEQTS path with no NODET retries. The errors are functionally benign — the link successfully trains to 56G PAM4 each time — but produce misleading false-alarm error register state.

Evidence Chain

  • Iter 1 WR_1 always clean, WR_2+ shows errors — rules out static HW defect; confirms WR-transition artifact
  • Iter 1 S0 always clean (same config, same knobs) — confirms S0/S1 asymmetry in WR recovery path
  • Iter 1 forcereconfig() clears all errors to 0x0 — confirms PF sticky register behavior (not real-time fault)
  • Iter 2 LTSSM trace: REC_RCVRLOCK@56G → Gen1 → 2× DET_ACT_128US NODET → DETALL — direct observation of detection failure
  • Iter 2 nodbmarkset=0x0 with dberr=0x1 — bus-level deskew timeout before lane identity established
  • Iter 2 eberr=0x8bff0000/0xefef0000 (wide, many lanes) — bus alignment failure, not SI-isolated lane fault

Recommended Fix

Primary fix: Investigate S1 receiver CDR lock timing / squelch threshold configuration. The 2× NODET before detection suggests S1 needs more signal settling time after WR at 2.5G. Options: (a) Adjust WR sequencing to add a delay before 2.5G detection on S1; (b) Check PCB trace length asymmetry between S0 and S1 UXI lanes; (c) Tune PciePhyInitOverride settings for S1 squelch threshold.

Workaround (immediate): Add ipc.forcereconfig() call in post-WR BIOS/FW sequence to clear PF sticky error registers. This prevents false-alarm accumulation without masking real failures.

Spec Reference: UXI Architecture Spec — LTSSM Detection State machine (DET_ACT_128US NODET/DETALL arcs); UXI Deskew Buffer behavior on detection timeout; PF register clear-on-WR requirements.
