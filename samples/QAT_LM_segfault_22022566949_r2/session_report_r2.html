Final Analysis

The comparative analysis of passing (6.18.5.2.5) and failing (6.18.8.4.9) logs has definitively invalidated three previously-cited indicators and identified the true differentiators:

  1. vtd_interrupt_remap_msi warning — DISCARDED: Appears in both passing and failing QEMU output. This is a cosmetic log in QEMU's VT-d emulation when the guest first raises an MSI before the interrupt remapping table entry is fully populated. It is not indicative of a fatal state.
  2. TSC skew — DISCARDED: The passing case has a -139ms TSC skew (12× larger than the failing case's -11ms) with zero crashes. The conclusion is clear: TSC skew is NOT causal. It is a side effect of imprecise TSC migration synchronization that occurs in both cases.
  3. IOMMU_IOAS_MAP BAR warnings — DISCARDED as root cause: These warnings appear identically in both the passing (source_VM) and failing (source_VM) logs. They are a known iommufd/VFIO limitation with PCI BAR alignment for QAT device 4949 — non-fatal and present in all configurations.
  4. NEW KEY DISCRIMINATOR — vfio-pci FLR completion: In the passing case, vfio-pci 0000:00:03.0: reset done is explicitly logged at [72s] and [85s] on the destination VM (within ~354ms of reset initiation). In the failing case, no equivalent reset done confirmation is observed in the destination dmesg. This strongly suggests the VF FLR (Function Level Reset) is not completing on kernel 6.18.8.4.9 in the VFIO migration path. A VF that fails to reset leaves its internal register state, completion queues, and interrupt vectors in a transitional state from the source. When cpa_sample_code fires its first completion callback at [98.8s], it encounters a null or invalid function pointer — hence the instruction fetch from address 0x0 (error code 44 = PFEC: I+U+~P).
  5. HSD Rev 5 confirmation: Engineer comment on 2026-06-09 explicitly states the issue reproduces on multiple systems and passes with CentOS 6.18 5.2.5 kernel (DMR BKC WW14). Component set to platform.operating_system.vmm.kvm. LFE 22022566950 created and assigned to Linux KVM team.
  6. PCI domain difference as secondary variable: PASS uses dest VF 0000:0f:00.2 (same domain 0000), FAIL uses 0001:0f:00.1 (domain 0001). This may exacerbate the regression if kernel 6.18.8.4.9 has a specific defect in handling multi-domain VF resets, but cannot be confirmed as primary without an A/B isolation test.

🔍 Best Current Hypothesis — Pending A/B Confirmation

Revised Root Cause / Primary Hypothesis (85%)

Kernel 6.18.0-dmr.bkc.6.18.8.4.9.x86_64 introduced a regression in the destination-side VFIO/KVM VF Function Level Reset (FLR) or state-restore path for migrated QAT SR-IOV VFs. In the passing case (kernel 6.18.5.2.5), vfio-pci reset done is logged on the destination at [72s] and [85s], confirming the QAT VF is properly reset before userspace accesses it. In the failing case (kernel 6.18.8.4.9), no reset done is observed — the VF may be left in an incomplete state from the source side. When cpa_sample_code fires its first completion callback at [98.8s] post-migration, it encounters uninitialized device state (null/invalid function pointer), causing an instruction fetch from address 0x0 (PFEC error 44 = U+I+~P) — a fatal segfault in libc.so.6.

⚠ Note: This hypothesis requires A/B isolation (same VF topology on both kernels) to fully confirm whether the kernel version alone is causal, or whether the PCI domain 0001 combination with 6.18.8.4.9 is the triggering condition. LFE 22022566950 is assigned to the Linux KVM team for investigation.
